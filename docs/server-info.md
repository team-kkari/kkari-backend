## 3. 네트워크

외부에서 열린 포트: `22`, `80`, `443`, `8501`, `1024~65535` (제공처 안내 기준)

- 앱은 `0.0.0.0`으로 바인딩해야 바깥에서 접속된다. 예: `http://<서버 공인 IP>:8000`
- 1024~65535가 모두 열려 있으므로 **PostgreSQL(5432) 등 DB·내부 포트도 바깥에 노출될 수 있다.** DB는 `127.0.0.1` 또는 Docker 내부 네트워크에만 바인딩한다.
- 외부로 나가는 통신은 가능: Maven Central, Docker Hub, `api.anthropic.com` 도달 확인.

## 7. 알아둘 점

- **디스크 30GB**: AWS 공개 가격표의 EC2 전체 파일이 약 9GB다. 통째로 받지 말고 필요한 부분만 잘라 쓴다.
- **서버는 x86_64**: Apple Silicon Mac에서 Docker 이미지를 빌드하면 아키텍처가 달라진다. 서버에서 빌드하거나 `--platform linux/amd64`로 빌드한다.
- **HTTPS**: 도메인이 없으면 인증서를 붙이기 어렵다. HTTPS 프론트에서 이 서버의 HTTP API를 부르면 브라우저가 막을 수 있다. 팀에서 도메인 필요 여부를 정한다.
- **단일 서버**: 장애 시 대체 서버가 없다. DB 백업은 S3로 보낼 계획을 세운다. 서버를 중지·재시작하면 공인 IP가 바뀔 수 있으므로 (고정 IP 여부 미확인) 임의로 끄지 않는다.
- **Docker 포트 공개**: `docker run -p`로 공개한 포트는 ufw 설정을 우회할 수 있다. DB 컨테이너는 `-p 127.0.0.1:5432:5432`처럼 로컬로만 공개한다.
- **컨테이너에서 Role 사용**: 기본 bridge 네트워크의 컨테이너에서 IMDSv2 토큰 요청(`PUT http://169.254.169.254/latest/api/token`)이 HTTP 200으로 성공했다 (2026-11-05). IMDS hop limit은 통과한다. 실제 Role 자격증명으로 `sts get-caller-identity`가 되는지는 백엔드 컨테이너 기동 후 확인한다.
